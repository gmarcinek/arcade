# Plan: tron-tunel-3 Milestones 2–4

## Metadata

- **Feature**: tron-tunel-3-m234
- **Status**: COMPLETE
- **Research**: none
- **Details**: [.copilot-tracking/details/20260504-140000-tron-tunel-3-m234.md](../details/20260504-140000-tron-tunel-3-m234.md)

## Goal

Replace the single 400-unit demo segment with an infinite streaming chunk system, then move the player onto the procedural surface (s/u coordinates), and finally wire safe-zone checks from `trackWorld` instead of the legacy `getArcHalfAngle`.

---

## MUST-HAVE

### Milestone 2 — Infinite chunk generation

- [ ] **M2-1 — proceduralConfig.js**: Create `src/procedural/proceduralConfig.js` with all generation constants.
  - Files: `src/procedural/proceduralConfig.js` _(new)_
  - Verify: imports cleanly from other procedural files

- [ ] **M2-2 — curves.js additive**: Add optional `initialNormal` param to `buildCurve(points, initialNormal?)` so chunks can seed the RMF from the previous segment's last normal (no-break change; old call with 1 arg still works).
  - Files: `src/procedural/curves.js`
  - Verify: `generateDemoTrack` still works; new call with `initialNormal` produces no flip at t=0

- [ ] **M2-3 — trackChunkManager.js**: Create `src/procedural/trackChunkManager.js` — sliding-window chunk pipeline.
  - Files: `src/procedural/trackChunkManager.js` _(new)_
  - Verify: `update()` generates N ahead, discards M behind; `advanceToNextSegment` returns correct id; debug renderer shows connecting segments with no visible gap

- [ ] **M2-4 — trackWorld additive**: Add `addSurface(seg)` and `removeSurface(id)` mutators to `createTrackWorld` return object so the chunk manager can register/deregister segments.
  - Files: `src/procedural/trackWorld.js`
  - Verify: `getFrame` / `getSafeInfo` on a just-added segment works; removed segment returns `null`

- [ ] **M2-5 — generateDemoTrack.js update**: Replace static single-segment generation with a call to `createTrackChunkManager` seeded at 42; return the chunk manager's `trackWorld`.
  - Files: `src/procedural/generateDemoTrack.js`
  - Verify: flythrough runs past 400 units and never hits a wall or hard cutoff

- [ ] **M2-6 — debugTrackRenderer.js update**: Iterate all `trackWorld.surfaces` (or a provided `getActiveSegments()` accessor) instead of hard-coding `surfaces[0]`.
  - Files: `src/procedural/debugTrackRenderer.js`
  - Verify: debug lines appear for every active chunk in the sliding window; old chunks disappear as player advances

### Milestone 3 — Player on procedural surface

- [ ] **M3-1 — state.js additions**: Add `activeSurfaceId`, `s`, `u`, `uVelocity`, `sVelocity` to `state`. Keep all legacy fields.
  - Files: `src/state.js`
  - Verify: no existing code breaks; new fields present with initial values

- [ ] **M3-2 — playerSurface.js**: Create `src/procedural/playerSurface.js` — `updatePlayerSurface(dt, left, right, jumpPressed, boostHeld, chunkManager)`.
  - Files: `src/procedural/playerSurface.js` _(new)_
  - Verify: `state.s` advances; `state.u` responds to left/right; segment boundary triggers `advanceToNextSegment`; `state.activeSurfaceId` updates correctly

- [ ] **M3-3 — playerSurfaceBasis.js**: Create `src/procedural/playerSurfaceBasis.js` — `getPlayerFrame(trackWorld)` returning a `SurfaceFrame`.
  - Files: `src/procedural/playerSurfaceBasis.js` _(new)_
  - Verify: returns valid `{position, forward, normal, binormal}` at any `state.s / state.u`

- [ ] **M3-4 — ball.js additive**: Export `updateBallPositionFromFrame(carGroup, frame)` — sets `carGroup.position` and orients it from `frame.normal` (up) and `frame.forward`.
  - Files: `src/ball.js`
  - Verify: ball visible at correct tube-wall position when `PROCEDURAL_PLAYER = true`

- [ ] **M3-5 — camera.js additive**: Add optional `proceduralFrame` parameter to `updateCamera(dt, camera, carGroup, proceduralFrame?)`. When provided, skip `carTheta` spring and use `frame.position / frame.forward / frame.normal` for placement.
  - Files: `src/camera.js`
  - Verify: camera follows player smoothly in procedural mode; legacy mode unchanged

- [ ] **M3-6 — main.js wiring (M3)**: Add `PROCEDURAL_PLAYER = false` flag. In `tick()`, branch on flag: call `updatePlayerSurface()`, `getPlayerFrame()`, `updateBallPositionFromFrame()`, `updateCamera(..., frame)`, `chunkManager.update(state.activeSurfaceId, state.s)`.
  - Files: `src/main.js`
  - Verify: flipping flag to `true` runs procedural path; `false` runs legacy path without any change
